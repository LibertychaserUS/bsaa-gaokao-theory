## 1. 位次归一化

### 1.1 变换：池内百分位，而非"归一化位次"

**结论：用百分位 u，不用位次差/位次比这类"归一化位次"。** 理由：位次差（如现状 scale=10000
常量差）隐含"位次间距的含义跨年不变"，但 N_total 逐年变化直接违反这个假设；百分位把
"排在多少人前面"这个语义直接换成"排在池的前 u 比例"，这个语义本身跨年是良定义的比较对象
（雷 3 的解法，`research_directions` §7 已定调）。

变换公式（对 T1 的 `min_rank`，池=全体，即 T2 `subject_pool='全体'` 对应的 `N_total(year)`）：

```
u = (rank − 0.5) / N_total(year)          # Hazen 连续性修正，rank ∈ {1,...,N_total}
```

用 `rank − 0.5` 而非裸 `rank / N_total`：裸公式在 rank=N_total 时给出 u=1（越过池边界，
与"顶部聚合区人数远小于 1"这类下游 Beta 分布近似不兼容）；`-0.5` 修正是标准顺序统计量
plotting-position 惯例（Hazen），且不引入任何需要标定的自由参数——**优先于**其他形式
（如 Weibull `rank/(N+1)`）的理由是与 `研究方向 §7 雷3`"顺序统计量在此尺度天然为 Beta"
的说法直接衔接（Beta 分布的分位数-位置对应关系用 Hazen 修正误差最小,可作为默认选择,
但非强约束——若下游校准子系统已锚定另一种 plotting position 约定,应统一到那个约定,
避免同一管线出现两套百分位定义）。

### 1.2 head_aggregate 区的百分位：先分清"位次侧"与"分数侧"两条链路

这是本节最容易踩坑的地方——**T1 的 min_rank 和 T2 的 head_aggregate 哨兵不在同一条链路上**，
必须先分清楚，再决定要不要处理：

- **位次侧（T1 → u，直接可用）**：T1 的 `min_rank` 本身就是位次数值（`exact` 时是投档系统内部
  已消除同分同位次歧义后的真实位次；`le` 时是位次上界如 50）。`u = (rank−0.5)/N_total` 对
  **任何** rank 值都是良定义的代数运算，**不依赖该 rank 对应的分数是否落在 T2 的顶部聚合区**。
  换句话说：清华"前50"这类顶尖专业的位次落在 T2 全体池的头部聚合区间内部（该区间人数
  gap≈42~49，50 明显落在其中），但这**不妨碍**把 50 直接换成 `u ≤ (50−0.5)/N_total`——
  这里唯一要处理的不是"聚合区"问题,而是"le 删失"问题(见下段)。
  **结论：T1→u 的转换对 head_aggregate 完全免疫，不需要特殊分支。**

- **分数侧（需要 score→u 反查时，才会撞上 head_aggregate）**：只有当某个下游用途需要
  "给定一个**分数**，查它对应的百分位"（例如 §2 的选科池交叉校准、或用一分一段表反推某个
  历史阈值分数对应的当年位次），才会用到 T2 的 `score → cum_count` 映射。在这条链路上，
  任何分数 `x > s`（`s`=该池首个非空白行分数，可能 < table_top）的 `cum_count(x)` 是
  **不可解析的**——原表在 `(s, table_top]` 区间完全空白，哨兵只给出这整段的**总数** gap，
  不给内部分布。此时百分位查询必须返回**区间**而非点值：
  ```
  u(x) ∈ [1/N_total, gap/N_total]   若 x > s（分数落在头部聚合段内）
  u(x) = (cum_count(x) − 0.5)/N_total   若 x ≤ s（正常逐分行，点值）
  ```
  下游任何消费这个反查函数的代码，必须显式处理 `x > s` 分支返回区间对象（例如
  `(lower, upper, censored=True)`），**禁止**用区间中点或 `gap/2` 之类的启发式塌缩成点值——
  这违反 D 区"删失不当精确值"的纪律，且该区间在物理/化学/全体池通常很窄（gap 小，
  即使塌缩误差也小），但在政/史/地池可能覆盖 15~20 个分数点，塌缩会掩盖真实不确定性。

- **对密度估计 f(x) 的连带影响**：`研究方向 §4` 的方差公式 `Var ≈ p(1−p)/[N·f²(x_p)]` 需要
  密度 `f`。头部聚合段内 `f` 无法用"逐分计数/池总量"直接估——该段的经验密度只能给出
  **段平均密度** `gap/(N_total·(table_top−s))`，作为该整段的近似常数密度使用（分段常数核，
  带宽=`table_top−s`），而不能假装有逐分辨率。M 区应在密度估计构件里对
  "`x_p` 落在头部聚合段"的情形显式打 `density_source='head_aggregate_avg'` 标记，
  提示该点的方差估计比正常区间更不可信（带宽人为放宽，方差应相应上调，而非直接套用公式
  给出虚假的高精度）。

### 1.3 与 le/missing 删失的组合

`min_rank_censor='le'` 的行（如"前50"）转成百分位后是**上界区间** `u ∈ (0, (50−0.5)/N_total]`，
不是点值；`missing` 的行**没有**百分位观测，不得填 0 或填均值，直接从依赖"具体位次值"的
统计构件（如阈值时间序列拟合、方差估计）中剔除，但**不**从台账/报告中剔除（沿用 T6 台账精神，
在 M 区自己的构件里保留"存在但不可用于点估计"的记录，供 §3 的实体史与 C 门的删失似然使用）。

## 2. 子科目池百分位 + 联合约束

### 2.1 问题的两层结构

山东"3+3"选科下，T2 按 7 个池（全体+6 个再选科目）分别给出一分一段表，但**投档/排位的官方口径
是全体位次**——T1 的 `min_rank` 全部是全体池位次，不是选科池位次（山东同一批次不分文理、
不按选科分列排位）。因此"某个专业组合的候选在其相关竞争池里的位次/百分位"**不是 T1 直接给的
数字，需要 M 区用一条 score 桥接构造**：

```
T1.min_rank(全体, exact) → [T2 全体池反查: rank→score]（§1.2 反查逻辑）→ score = s*
                                                                      ↓
                                          T2 目标选科池(如物理): score s* → cum_count_物理(s*)
                                                                      ↓
                                          u_物理 = (cum_count_物理(s*) − 0.5) / N_物理(year)
```

**边界**：这条链路要求 `s*` 落在目标选科池自身有逐分数据的区间 `[s_pool, 150]`；若 `s*` 落在
该池自己的头部聚合区（`s* > s_pool`），则 `u_物理` 也只能给区间（同 §1.2）。此外，全体池反查
`rank→score` 本身若 `rank` 落在**全体池**的头部聚合区（罕见，全体池 s 几乎=table_top，
故这一步通常不受影响；但政/史/地作为目标池时会因为该池自身聚合区更宽而更容易撞上）。

### 2.2 单科要求（如"物理"）：直接用上面的桥接，无需 Fréchet

单科要求专业组的"相关竞争池"就是该科选考池本身，2.1 的桥接给出点值或区间即可，不需要区间估计。

### 2.3 联合要求（如"物理+化学必选"）：真实联合分布不可得，只能给区间

T2 不提供选科**组合**的联合分布（不是"物理池"和"化学池"各自内部再交叉表），因此"物理+化学
双选学生"这个子群体的规模和其内部的分数分布都不是直接观测量。M 区处理方法——**在每个分数阈值
上做 Fréchet-Hoeffding 区间估计**，而不是先估总量再假装均匀展开：

设 `T(x)` = 全体池在分数 ≥x 的累计人数（`cum_count_全体(x)`），`A(x)` = 物理池同口径，
`B(x)` = 化学池同口径，则物理∩化学联合池在同一阈值上的累计人数 `J(x)` 满足：

```
max(0, A(x) + B(x) − T(x))  ≤  J(x)  ≤  min(A(x), B(x))
```

这是**逐阈值**的 Fréchet 界（比研究方向文档给出的"年度总量"界更细——年度总量界是
`x=150`（即分数下界=全部报名者）时的特例，`T(150)=N_total`，与文档 §7.9 附录给出的
"2026 物≈化 差<1%"一致，可作为该特例的数值校验锚）。由此，联合池百分位本身也只能给区间，
而不是把"联合池总量"的区间和"某分数以上联合人数"的区间分别算完再直接相除（两个区间独立
取端点相除会人为放大误差，应保持配对关系）：

```
u_joint(x) ∈ [ max(0, A(x)+B(x)−T(x)) / min(A(150), B(150)) ,
               min(A(x), B(x)) / max(0, A(150)+B(150)−T(150)) ]
```

（下界用"小分子/大分母"、上界用"大分子/小分母"，保证区间方向正确；若
`A(150)+B(150)−T(150) ≤ 0`（即两池加总未超全体，Fréchet 下界退化为 0，2026 实测
`343381+341401=684782 < 708817`，恰好属于这种情况），上界公式分母为 0，**该联合池百分位的
上界不可用**，只能报告"联合池百分位下界 + 上界=不可估（数据不足以约束）"，不得强行给一个
数值——这是真实的认识论限制，不是实现缺陷。

**处理建议**：
1. 把 `u_joint` 的区间宽度本身当作一个**特征**往下传（宽=约束力弱，如上例分母塌缩到 0 的场景），
   而不是找个点估计（如区间中点、独立性假设下的乘积估计）当真值喂给校准/DP 层——这类点估计
   隐含"两科选择独立"的假设，而现实中选科强相关（比如选物理的学生选化学的条件概率远高于
   边际概率），乘积估计会系统性低估联合池规模，是一个隐蔽但方向确定的偏差源。
2. 若后续拿到官方选科组合分布（哪怕只是抽样统计），应作为**外部先验**去收窄这个区间，
   而不是替换掉区间机制本身——区间机制作为"无先验时的诚实兜底"应始终保留作 fallback。
3. "或"关系（如"物理或化学"）用对偶的并集 Fréchet 界：
   `max(A(x),B(x)) ≤ union(x) ≤ min(T(x), A(x)+B(x))`，同样逐阈值构造，同样只给区间。
4. 这个区间对象天然是 §5（混合模型）里"chance theory"要处理的不确定量的一种来源——
   录取概率 p_i 的输入若依赖联合池百分位，其不确定性应该显式向上传播，而不是在 M 区内部
   就被悄悄塌缩成一个点，破坏了"录取端也可以有结构性不确定"这条本该保留的信息。

## 3. 实体阈值史拼接（依赖 T5 xwalk）

### 3.1 拼接的基本形态

对每个 `entity_id`（T5），M 区把该 entity 在各年命中的 T1 行的 `(year, min_rank, min_rank_censor)`
按 year 排列成时间序列，再套 §1 的百分位变换得到 `(year, u, u_type)` 序列（`u_type` ∈
{point, upper_bound, unobserved}，对应 exact/le/missing）。这个序列是 §4 政策掩码、
C 门校准回归的直接输入。

### 3.2 M3（人工）/unmatched 的处理——不能一刀切

T5 的 `match_method` 有三档，M 区必须区分对待，不能把 M1/M2/M3 一律当"同等可信的一个点"：

- **M1（精确匹配）**：直接拼接，权重=1（正常观测）。
- **M2（组内消歧）**：直接拼接，权重=1——这一档是靠 identity 注记精确对齐或"组内各恰1条"
  的确定性规则做出的，不是模糊匹配，可信度与 M1 同级，D 区规范（M2 定义）已明确排除了
  编辑距离/embedding 类模糊匹配，故不需要额外降权。
- **M3（人工审核，已回填）**：拼接，但**降权/展宽不确定性**，不与 M1/M2 同等对待。理由：
  M3 触发的前提是"多对多仍不唯一"，即使人工最终拍板一个对应关系，这个判断依赖的信息
  （注记漂移、计划数/位次参考）本身允许存在小概率误判（尤其当两年该专业内容发生了实质性
  变化但恰好维持同一 `match_key` 组），人工判断的置信度应体现在 T5 的 `match_confidence` 列上。
  M 区做法：把这条时间序列链接的**观测方差**按 `match_confidence` 反比展宽（例如
  `Var_effective = Var_base / match_confidence`，或更简单地设一个离散乘子——具体函数形式
  留给 C 门校准子系统按实际 `match_confidence` 取值分布决定，M 区只需保证这个权重信号
  从 T5 传递到序列对象上，不在 M 区内部就被抹平成"一个普通观测点"）。
- **M3 无法回填 / M5 unmatched（真正拼不上）**：**不产生跨年阈值史点**，这是设计上的
  "缺失"而不是"错误"（T5 M5 条款原文：unmatched 不是错误）。M 区需要区分两种子情形，
  分别路由到不同的下游处理，而不是笼统丢弃：
  1. **新设专业**（该 entity 只在较晚年份出现）：没有自身历史可拼，路由到**冷启动构件**——
     用同校其他专业当年阈值百分位的分层均值/收缩估计（对应研究方向文档 §7.8"新设专业=
     冷启动走分层收缩"），M 区的产出是给这类 entity 打一个显式标记
     `xwalk_history_len=0, cold_start=True`，供下游知道"这条没有时间序列可用，别硬套
     时间序列模型，改用截面分层模型"。
  2. **停招/消失专业**（只在较早年份出现，不会是 2026 候选）：对 2026 预测无直接影响，
     但要计入"跨年可比样本占比"统计（雷 8 幸存者偏差的一部分），因为如果不看这个比例，
     阈值史训练集会隐性偏向"存活到现在的专业"，其阈值可能系统性不同于停招专业。
- **序列内部的"断点"**（entity 在 2022/2023/2025 都匹配上但 2024 那年因为 M3 没回填/
  M2 组内失败而缺失一年）：**保留为缺失，不插值**。下游拟合方法必须是"能吃缺失年份"的
  （如状态空间模型按观测年份跳跃更新，而不是假设等间隔完整序列），这条纪律和 D 区
  P2"无声即错"的精神一致——插值等于用模型的输出去填模型的输入，会制造虚假的连续性信号。
- **报告义务**：M 区管线对每个训练用年对，必须输出 M1/M2/M3(按 confidence 分桶)/unmatched
  各自的计数与占比（直接对应 D 区规范 M5 的"报告必须列出 unmatched 计数与占比"要求，
  M 区在此基础上把 M3 也做分桶统计，因为 M3 不是二元的"匹配/不匹配"，是一个连续可信度轴）。

## 4. 政策年对有效性掩码

### 4.1 掩码不是"按年份一刀切"，是"按实体×年对"

`research_directions` §7.10 的主线裁决是：山东普通类常规批 2022-2026 **机制层（①）无断层**，
唯一实质影响主线的是 2023→2024 的**选科要求断层（③需求层）**，且这个断层**只打理/工/农/医子集**
（文史经管类不受影响）。这意味着"年对有效性掩码"**不能**是一张只按 `(y1,y2)` 索引的全局布尔表——
同一个 `(2023,2024)` 年对，对张三专业（理工）是无效训练对，对李四专业（文史）是有效训练对。
M 区必须把掩码做成**实体级**（或至少"专业选科要求类别级"）的构件，索引是
`(entity_id 或 match_key, y1, y2)`，不是 `(y1, y2)` 两个字段。

### 4.2 判定规则（从已有数据可机械算出的部分）

| 断层来源 | 判定数据源 | 规则 |
|---|---|---|
| 需求层③选科断层（2023→2024） | T3 `subject_req_norm`（雷13 唯一数据源，规范明文禁止从 T1 注记推断） | 若该 entity 在 y1/y2 两年 `subject_req_norm` 不同，且年对跨越 2023→2024 边界 → 该年对对该 entity 标记无效（`SUBJECT_REQ_BREAK`）；若两年 `subject_req_norm` 相同（含都不受影响的文史经管类）→ 有效。**注意**：T3 主计划本 2022/2023 未必齐全（见 §5），若某 entity 在 y1 年缺 `subject_req_norm` 观测，判定规则必须**fail-closed**（缺数据默认标记无效/不可判定，不得默认为"无变化"）。 |
| 类别层⑤重组 | T5 匹配结果本身 | 若该"年对"下这个 entity 走的是 M3-unmatched 或 M2 高度依赖 identity 注记重排，本质上就是 §3 的实体史断点，不单独需要新构件——但若怀疑是类别重组（如目录调整）而非单纯行政噪声，掩码的 `reason_code` 应记 `CATALOG_REORG` 以区别于普通的 M3 不确定性，方便复核区分"两个东西本来就不是一个东西"和"两个东西是一个东西但匹配置信度低"。 |
| 2025→2026 批次构成变化（雷23） | T1/annotations 的 identity 注记（专项/公费/定向类） | 若 entity 在 2026 侧携带"新并入"的特殊类型 identity 注记（专项/公费医学生/3+2 贯通等）而 2025 侧该 entity 没有对应注记或不存在，则该年对标记无效（`SPECIAL_TYPE_MERGE`），避免把"原来在特殊类型批"的阈值和"现在挤进常规批同一份文件"的阈值直接接续当同一序列点；反之若 2025/2026 两侧 identity 注记一致（都是常规无特殊标记，或都带同一类专项标记且此前已在常规批出现——规范附录已指出 2023/2024 主表已有内嵌先例），机制不变，掩码有效。 |
| 机制层①（结构开关，当前主线不触发） | 无需山东本地数据，是政策断层年表本身的判定结果 | 保留为一个全局硬开关（若未来年表更新出现真正机制断层，直接把该年对对**全部** entity 置无效，无需逐 entity 判断——这是唯一允许"按年份一刀切"的层级，因为机制层断层不区分专业类别）。 |

### 4.3 落地形态：独立于 xwalk 的第二道闸

**掩码表和 T5 xwalk 是两件不同的事，不能合并**：xwalk 回答"这两行是不是同一个东西"，
掩码回答"就算是同一个东西，这两年的观测能不能放在一起训练"。一个 entity 完全可能
M1 精确匹配成功（同一个东西没有疑问），但年对掩码仍判无效（比如该专业 2023→2024
选科要求从"物理或化学"变成"物理+化学"，`match_key` 里的 `major_base` 没变所以 M1 照样
匹配上，但学生池已经结构性变了）。M 区的产出是一张独立构件：

```
year_pair_mask(entity_id, y1, y2) → {valid: bool, reason_code}
reason_code ∈ {OK, SUBJECT_REQ_BREAK, CATALOG_REORG, SPECIAL_TYPE_MERGE,
               MECHANISM_BREAK, INSUFFICIENT_DATA}
```

这张表直接挂到 `acceptance_gates_v1.md` 已经点名的两个门上——**TR1**"训练数据装载 API
按年份+regime 掩码物理隔离"（构造上不可达，不是事后审计）和**C2**"年对掩码生效"
（要求机器抽查 100 对验证）：M 区交付这张表本身，训练侧代码只需要在构造 DataLoader 时
按这张表过滤，不需要（也不应该）自己重新判断断层逻辑。

`INSUFFICIENT_DATA`（新增，供 fail-closed 规则使用）：当判定所需的输入本身缺失
（如 T3 该年该专业 `subject_req_norm` 未覆盖）时的兜底 reason_code，与"判定为有断层"
区别对待（下游可以选择性地把这类当作"暂不可用"而非"确认不可比"，为将来数据补全后
重新判定留出口），但在没有额外证据前**效果上等同于无效**（不得默认放行）。

## 5. 2026 供给 lag-proxy

### 5.1 已定的代理方案（来自 declarations 声明，M 区照此落地，不重新决策）

- **宇宙（候选专业全集+选科要求）**：NewsID=6819（2025-03-17 发布，"2024 通用版"选科要求表，
  续用 25/26 届）。
- **配额 m（`plan_count`）**：2025 年该 entity 投档表 `plan_count` 列（T1/T3 侧滞后一年代理）
  + NewsID=7268（2026-06-27，本科补充信息）里的显式修正。
- 这个方案已经在 `declarations/计划发布形态声明_2025_2026.md` 定案，M 区的任务是把它变成
  **带来源标记和不确定性量化的构件**，不是重新论证要不要用代理。

### 5.2 M 区需要补的两个环节

**环节 A：把 NewsID=6819 的宇宙接入现有 xwalk 空间。** T5 现有的 xwalk 是在 T1/T3 的
`(school_code, major_code)` schema 内部做的（2022-2025 之间）。NewsID=6819 是一份**公告文本**
（选科要求表），其行大概率是 `(school_code, major_name)` 或类似口径，未必带 T1/T3 使用的
`major_code`（`major_code` 本来就"只作年内键"，2026 招生年尚未发生，不存在天然的 2026
`major_code`）。这意味着"把 6819 的专业和历史 entity 对上"是一次**新的**匹配任务，
不能假设 T5 现有的 M1-M5 产出已经覆盖它——M 区需要把 6819 的名录当成一个新的"年份节点"，
套用 T5 同一套 `match_key`（R8：`school_code + major_base + identity 注记`）逻辑去匹配到
已有 entity 空间，产出物同样区分 M1/M2/M3/unmatched，且**unmatched 里的"新增"部分**
就是 2026 真正的冷启动候选（§3.2 第 1 类）。

**环节 B：给 lag-proxy 配额打不确定性标签，不是给一个裸数字。**

```
quota_2026_hat(entity):
  若 entity 在 2025 有 T1/T3 plan_count 观测且 NewsID=7268 无修正 →
      value = plan_count_2025, source = 'lag_proxy_2025', 
      uncertainty = 该 entity（或同校/同类）历史 Δplan_count(y→y+1) 的经验分布
                    （用 2022-2025 四年间已观测到的逐年计划数变化幅度，
                      作为"预计代理与真值偏离多大"的先验尺度，而不是假设零变化）
  若 entity 在 7268 补充信息中有显式修正数值 →
      value = 修正后数值, source = 'lag_proxy_2025_corrected', 
      uncertainty = 收紧（官方已发布修正，比纯代理更可信，但仍非当年原生全量计划本，
                    不应等同于 2022-2025 那种"原生"配额的确定性）
  若 entity 属于雷23"特殊类型批并入常规批"新增类别 →
      不得直接借用某个"同名"常规批 2025 plan_count（跑道不同，量级可能完全不可比）；
      若能找到该专业在其**原跑道**（如原特殊类型批）2025 的计划数 →
          value = 该数值, source = 'lag_proxy_cross_track_2025', uncertainty = 更宽
      否则 → source = 'cold_start_unknown'，不给点值，走截面兜底（同 §3.2 第 1 类机制）
  若 entity 在 2025 及 6819 均无法建立对应（真正的 2026 全新专业）→
      source = 'cold_start_unknown'，同上
```

**环节 C：向下游暴露的义务。** `quota_source` 与不确定性尺度必须作为显式列跟随
`quota_2026_hat` 一起进入后续任何消费它的构件（G_p 回归的"计划数"结构协变量、
F1 冻结文件的协变量表），使得"计划数年际变化"作为已声明的预测误差来源（declarations
文档第 4 点、`acceptance_gates_v1.md` F1 冻结声明的组成部分）在数字层面可核查，而不是
论文/报告里一句话声明、实现里却把 2026 的代理配额和 2022-2025 的原生配额一样对待，
造成"声明了披露、实现没做披露"的两套口径不一致（这本身也是本文档系列该规避的一种雷）。

## 小结（给主循环/其他 M 区 agent 的接口清单）

本文件产出的四个可复用构件（尚未实现，供后续实现 agent 对齐接口）：

1. `percentile(rank, year, pool='全体') -> (u, u_type)`：§1，Hazen 修正 + le/missing 处理。
2. `score_to_percentile(score, year, pool) -> (u_or_interval, censored: bool)`：§1.2/§2.1，
   头部聚合区返回区间。
3. `joint_pool_percentile(score, year, pools=[...], relation='and'|'or') -> interval`：§2.3，
   逐阈值 Fréchet 界，不塌缩成点值。
4. `entity_threshold_series(entity_id) -> [(year, u, u_type, xwalk_weight)]`：§3，M3 降权、
   缺口不插值、cold_start 显式标记。
5. `year_pair_mask(entity_id, y1, y2) -> (valid: bool, reason_code)`：§4，实体级掩码，
   独立于 xwalk 本身，fail-closed。
6. `quota_2026_hat(entity) -> (value_or_none, source, uncertainty)`：§5，lag-proxy + 显式来源/
   不确定性标签，特殊类型并入与冷启动分流。

共同纪律：**任何删失/不可得信息只能表达为区间、缺失标记或显式来源标签，不得塌缩成
看似精确的点值**——这是贯穿本文件五节的唯一原则，也是与 D 区"删失不能喂算法"的
交付契约的对接点。
