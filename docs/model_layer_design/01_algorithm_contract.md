## 1. DP/BSAA 精确求解器的精确输入签名

### 1.1 无配额版（LEMMAS A3，对应 `verify_dp_exact.mjs`）

按值降序排列后的递推：
```
g(i, k) = max( g(i+1, k), p_i · v_i + (1 - p_i) · g(i+1, k-1) )
g(i, 0) = 0；g(N, k) = 0
```

逐字段签名：

| 字段 | 记号 | 类型 | 定义域 | 是否可省略 |
|---|---|---|---|---|
| 候选标识 | `id` | string（唯一） | 非空 | 否——DP 状态与回溯重建都靠 id 定位候选 |
| 录取概率 | `p_i` | number | `[0, 1]`（闭区间；`p_i=0`/`p_i=1` 是合法边界，ALG6 明确要求边界完备） | 否——DP 递推的乘法结构直接消费它 |
| 路径价值 | `v_i` | number | `≥ 0`（现有代码 `assertNonNegativeValue` 强制非负；LEMMAS 约定 `0 ≤ v`） | 否——排序键 + 递推第二项系数 |
| 志愿容量 | `n`（或 `k` 的上界） | 非负整数 | `[0, N]`（`k>N` 时按 ALG6 应退化为 `k=N` 的解，不 crash） | 否——DP 状态第二维 |
| 候选总数 | `N` | 非负整数 | 由候选列表长度隐含 | 是（隐含字段，不需要单独传） |

**注意排序前提**：DP 递推的正确性依赖候选**已按 v 降序排列**（LEMMAS A3 陈述"设全体候选按 v 降序
排成列表 L"）。这意味着 M 区交付契约里，**排序本身不是求解器的职责，而是契约构造阶段就应完成的
前置步骤**（或求解器内部先排序——工程实现选择，但数学契约上 v 降序是前提，不是可选项）。

**边界完备性（ALG6，M 区交付时需同时满足）**：空表（N=0）、全 p=0、全 p=1、k=0、k>N、单候选，
DP 都要有定义输出（0 或该候选自身价值），不得 NaN/crash——这是求解器实现的责任，但 M 区交付的
`(p_i, v_i)` 若本身含 NaN/Infinity（例如某候选的 p_i 估计失败），必须在契约层就被拒绝或显式标记，
不能把 NaN 传递给求解器让它在边界完备性测试之外"意外地"表现良好。

### 1.2 配额版（对应 `verify_dp_quota.mjs`，冲/稳/保配额约束）

在 1.1 基础上状态加一维（安全票数计数），签名新增：

| 字段 | 记号 | 类型 | 定义域 | 备注 |
|---|---|---|---|---|
| 安全阈值 | 阈值常数（现有脚本硬编码 `p≥0.8`） | number | `[0,1]` | **M 区交付契约应把这个阈值参数化**，不能沿用脚本里的硬编码 0.8；阈值本身属于"政策/参数三分法"里的产品配置常数，需带出处（见 `research_directions` §6 参数三分法：政策/合规常数"冻结为带出处的显式配置，禁止学习"） |
| 配额下限 | `q` | 非负整数 | `[0, n]` | "至少 q 个候选满足安全阈值"的硬约束 |
| 每候选是否达阈 | `safe_i`（派生量，非独立输入） | boolean | — | 由 `p_i ≥ 阈值` 直接算出，**不需要 M 区单独提供**，但 M 区必须保证 `p_i` 本身的估计口径与阈值定义在同一概率口径下（`research_directions` §4"全系统唯一概率口径"），否则阈值判定失真 |

配额版当前只验证了**单一配额区间**（"≥q 个 p≥0.8"）。若产品侧要做完整的冲/稳/保三段配额
（`src/domain/scoring.ts` 的 `defaultProbabilityBuckets` 定义了 reach/steady/safety 三个区间），
配额 DP 需要状态维再扩展为多段计数——**这是求解器扩展的问题，不改变 M 区的输入字段类型**，
M 区只需保证 `p_i` 到位，分段边界由算法侧/产品侧配置层决定。

### 1.3 求解器不认识、也不应该认识的字段（ALG7 内核纯净性门）

`docs/acceptance_gates_v1.md` "设计法则·复杂度外置"段已经明确：**求解器签名永远只收
`(候选(p,v)列表, k, 冲稳保配额)`**。性别限制、色盲色弱、外语语种、面试政审、单科成绩、专项资格、
体检结论等资格性约束**不是求解器输入字段**，而是候选宇宙构造阶段（M 区职责的一部分）的
**过滤谓词**：`合格宇宙(学生) = {c : ∀ 谓词 P_c, P_c(学生问卷) = true}`。

**对 M 区的直接含义**：M 区交付给求解器的候选列表，必须是**已经过资格过滤**的候选列表；
资格谓词本身（从 D 区 T1 annotations_json 派生的 identity 注记 + 问卷侧硬约束事实）是 M 区的
上游产物，但**不作为字段传给求解器**，只作为"是否把这个候选放进列表"的二元决策，过滤完成后
即从契约中消失。

## 2. 排序定理（distribution-free / value-index）对输入的依赖边界

LEMMAS A2（逐点排序定理）的陈述范围：

> 对任意固定 ω 与底集相同的两个列表：(a) `payoff x ω ≤ maxOver (S ∩ admitted ω) v`；
> (b) 若 x 按 v 降序，则取等。推论：对**任意** ω 上的权重分布（不要求独立、不要求乘积形式），
> v 降序排列在同底集的所有排列中最大化期望 payoff。

**依赖边界拆解**：

- **排序结论只依赖 v，不依赖 p 的具体数值、不依赖 p 之间的联合分布**（"不要求独立、不要求乘积形式"
  是 A2 的核心卖点——这是"distribution-free"的字面含义）。换句话说，**排序阶段的输入契约只需要
  `v_i`**，`p_i` 对排序本身是零信息量的——它只在"选哪些候选进 S"和"算期望效用数值"两步起作用。
- **但 DP 阶段（A3）二者都需要**：递推式 `p_i·v_i+(1-p_i)·g(...)` 同时用 `p_i` 与 `v_i`。
  也就是说，"排序无关"的量只有一个：**给定候选集合后的排列顺序**这一件事本身；
  "排序相关但求解器仍需要"的量是 `p_i`——它决定**选哪 k 个**（子集选择问题），
  只是不决定**选中之后怎么排**。
- **推广到退档折扣（LEMMAS A5，v2 待办）**：ṽ_c = (1-r_c)v_c + r_c·v_dead 替换 v_c 后，
  排序定理退化为"交换论证"（不再是 distribution-free 逐点性，需要独立性/因子模型假设，
  LEMMAS 已显式声明这一退化）。**对 M 区的含义**：M 区若要交付 ṽ_c 而非 v_c，必须同时在契约
  元数据里声明"本次交付的排序保证退化为交换论证口径，非 A2 的分布无关口径"——这是一个理论保证
  强度的标注义务，不是数值本身的问题。
- **混合模型下（B2/B3）**：排序定理对 v 换成 v̂=E[V_c] **原样成立**（B3(b) 明确"排序按 v̂ 降序、
  选择由 A3 的 DP 精确给出"）。即"排序无关量=分布形状"这一结论在混合模型下进一步加强为
  "排序只需要 v 的期望值，完全不需要 v 的分布形状本身"（B2 的"不需要 V_c 之间任何独立性假设"
  再加上这一条，构成 M 区交付 v̂ 而非完整分布的理论正当性）。

**一句话边界**：排序=只认 v（或 v̂）；DP 选择=v 和 p 都要；p 的联合分布结构对两者都不需要
（distribution-free 覆盖排序，Fréchet 最坏界覆盖"至少一个录取"的安全性，都不需要联合分布）。

## 3. 混合模型中 p_i 与 v_i 各自的输入契约

### 3.1 p_i：给定候选位次 r，候选项目 i 的录取概率

`research_directions` §4 校准范式："估录取概率 → 估**阈值预测分布** G_p，p = 1−G_p(R)"。
拆解成 M 区必须提供的中间量：

| 中间量 | 记号 | M 区职责 | 依据 |
|---|---|---|---|
| 候选学生位次（当年/当次） | `R`（或百分位 `u=R/N_total`） | 提供，来自学生输入 + 当年 N_total（T2 全体池累计） | 学生侧输入，非 D 区派生，但 N_total 归一化是 M 区职责（§7 雷 3） |
| 阈值预测分布 | `G_p(·; θ_i)`（每候选项目一套参数，或分层共享参数） | **M 区核心交付**——不是 D 区直接提供的列，是从 T1 历史 min_rank（含删失）拟合出的统计构造 | `research_directions` §4；`probabilityCalibration.ts` 现有实现（logistic 拟合）是这一职责的现有（待升级）落地 |
| 阈值分布的方差/密度 | `Var ≈ p(1-p)/[N·f²(x_p)]`，`f` 由一分一段表给出 | M 区派生（结构化异方差），`f` 直接来自 T2 | `research_directions` §4"结构地基" |
| 删失似然贡献 | T1 `le`/`missing` 行的似然项（累积概率而非密度） | M 区必须在拟合 `G_p` 时正确处理，不可点估计化（详见 `docs/model_layer_design/02_censoring_treatment.md`） | 雷 2 清零后仍需处理删失，与"泄漏"问题独立 |
| 最终 p_i | `p_i = 1 - G_p(R; θ_i)` | M 区计算并交付给求解器的**唯一数值**（或数值+置信区间） | — |

**求解器只消费最终 p_i 这一个标量**（DP 递推里就是一个数）；`G_p` 本身、其参数 `θ_i`、
其方差结构，全部是 M 区内部的构造过程，**不进入求解器签名**，只在 M 区交付契约的
"来源可追溯性"元数据里出现（呼应 P5 可复算纪律：p_i 数值应可回溯到 `θ_i` + 拟合脚本版本）。

**混合模型下 p_i 是否需要改变**：不需要。B2/B3 的折叠只发生在价值侧（v→v̂），
录取端的随机性结构（p_i 本身、以及"每次实现只有一个候选兑付"的吸收结构）完全不受影响——
LEMMAS B2 的证明前提就是"录取随机性与价值不确定性定义在独立的两个空间上"（雷区 §7-5 第 6 条,
"B2 的建模公理需显式声明"）。**M 区交付契约上的直接后果**：p_i 的估计管线（校准子系统）
与 v_i 的估计管线（专家启发/原型打分）在契约层完全解耦，二者只在"每个候选一对 (p_i, v_i)"
这个最终元组上汇合，互不需要对方的中间产物。

### 3.2 v_i（v̂_i）：候选的路径价值（不确定性下取期望）

`research_directions` §5 混合模型核心设计：

> 不确定变量的层级设在**原型层**（约 7-15 个），非逐候选层——专家只能给原型打分；
> v_c = 数据属性 μ(c) 与不确定原型量的确定性函数

拆解：

| 中间量 | 记号 | M 区职责 | 依据 |
|---|---|---|---|
| 候选的原型匹配度向量 | `μ(c)` = `prototypeValues`（现有代码字段名） | M 区从 D 区数据派生（学校层次/专业匹配/地域匹配/供给稀缺度等，见 `candidateProjection.ts` 现有的 `schoolPlatform`/`majorFit`/`regionFit`/`costFit`/`majorSupplySafety` 等函数——这些正是 μ(c) 各维度的现有实现） | `candidateProjection.ts` 已有落地，但目前是**确定性配置常数打分**，非不确定变量 |
| 原型层不确定权重 | `π_m`（专家/学生偏好，可为不确定变量） | **不是 D 区数据，是问卷/专家启发输入**——M 区消费，不生产 | 参数三分法："价值/偏好参数...专家启发+不确定统计；禁止用录取数据训练" |
| 原型不确定量的期望 | `E[V_c] = Σ_m π_m · μ_{c,m}`（若共单调，用 B4 线性折叠） | M 区计算 v̂_c，作为求解器的 `v_i` 输入 | LEMMAS B2/B3/B4 |
| （v2）价值分位数/机会约束扩展 | — | **明确排除在当前契约外**——LEMMAS B6 边界声明"非线性准则不可分离，为开放问题" | 雷区 §7-5 |

**求解器只消费 v̂_i 这一个标量**（对单一目标场景；若走多原型帕累托前沿如
`paperTheory.ts` 的 `buildParametricParetoFrontier`，则消费的是原型价值向量 + 一组偏好向量，
但每次固定偏好向量运行时仍是标量流水线，不改变单次求解的字段类型）。

**混合模型下 v_i 的关键简化（B2 的价值）**：**不需要 v_c 之间的独立性假设**——这意味着
M 区在派生 μ(c) 的多个维度时，完全不需要操心"学校层次分与专业匹配分是否相关"这类问题，
折叠到 v̂_c 之后这个相关性结构自动消失（每次实现只有一个候选兑付，是"单变量兑付"结构，
不是多变量联合抽样）。**唯一要小心的是双计入**（雷区 §7-5 第 7 条）：若 v_c 已经含
schoolPlatform/majorFit 等维度，产品成本项 `strategy_axis_penalty` 若重复计入同一维度会造成
系统性偏差——这是 M 区与产品侧的接口审计义务，不是数学契约本身的问题。

## 4. 逐项标注：D 区已有 / M 区需派生 / 完全缺失需外部

| 求解器输入字段 | 状态 | 来源 |
|---|---|---|
| `id`（候选唯一标识） | **D 区已有** | T1 主键 `(year, round, level, school_code, major_code)` 的稳定投影（当年快照，非跨年 entity_id） |
| `p_i`（最终录取概率标量） | **M 区需派生** | 从 T1 历史 `min_rank`（含 `min_rank_censor`）拟合 `G_p`，结合当前学生 `R`/`u` 计算；派生链条=T1→残差池→删失似然拟合→G_p→p_i |
| `v_i`（v̂_i，路径价值标量） | **M 区需派生（部分）+ 完全缺失需外部（部分）** | μ(c) 的数据属性维度（学校层次/专业匹配/地域匹配/供给稀缺度）从 D 区 T1（school_code/major_name/plan_count 等）+ 外部院校层次库派生；但**原型偏好权重 π_m 完全不在 D 区，也不在任何现有数据源里**——这是问卷侧的纯外部输入，D 区不产生任何形式的"学生偏好"数据 |
| `n`（志愿容量） | **完全缺失需外部** | 学生填报的志愿位数上限，产品配置（山东 2025 前 96 志愿位，2026 起变化——`research_directions` §7.10 已记录批次构成变化雷 23），非 D 区数据 |
| `q` / 安全阈值 / 分段边界（配额 DP） | **完全缺失需外部** | 产品/政策配置常数（冲/稳/保分段阈值 `defaultProbabilityBuckets` 现有默认值 reach[0.1,0.3]/steady[0.4,0.7]/safety[0.8,1.0] 属产品侧配置，非从 D 区统计得出，需带出处并冻结，见参数三分法） |
| 资格过滤谓词（性别/色觉/语种/体检/政审/专项资格） | **D 区已有（原始信号）+ 完全缺失需外部（学生侧事实）** | 谓词定义从 D 区 T1 `annotations_json` 的 identity 注记派生（`data_cleaning_spec_shandong_v1.md` R6/T7 设计），但学生自身是否满足谓词（如是否色弱、是否愿意面试）**完全不在任何数据源中**，必须问卷采集 |
| 退档相关折扣量 `r_c`、`v_dead`（A5/A6，v2） | **完全缺失需外部** | LEMMAS 明确"r_c 不可由本数据估计，须由章程/体检规则外部界定"（`research_directions` §7.9 实证雷 20 结论）；`v_dead`、"绝不接受专业"清单归学生问卷（参数三分法：归学生本人） |
| 服从调剂决策 flag `a_c`（A6，v2） | N/A——山东"专业+院校"模式无调剂概念 | `research_directions` §7.7"机制红利"：a 在山东退化，A5/A6 是"推广到专业组省份的一般化定理"，山东主线不需要这个字段 |

**补充说明——为什么 `p_i` 标注为"M 区需派生"而非"D 区已有"**：D 区 T1 提供的是历史
`min_rank`（多年的观测点，带删失标记），这是**训练数据**，不是 p_i 本身。p_i 是"给定当前学生位次"
这一条件下的一个**预测量**，必须经过校准模型（拟合+推断）这一步才能产生，D 区不做任何形式的
预测，只做事实清洗——这条边界正是 M 区存在的理由。

## 5. M 区 → 算法的接口契约草案

### 5.1 输入：一个候选查询 + 候选程序列表

```
SolverQuery {
  student: {
    rank: number,                    // 当前学生位次（原始位次，非百分位——百分位归一化是 M 区内部计算细节）
    year: number,                    // 报考年份（用于选择正确的 N_total、正确的 G_p 参数版本）
    subjectPool: string,             // 选科池标识（对应 T2 subject_pool，用于选择正确的百分位归一化基准）
    eligibilityFacts: {...},         // 问卷采集的硬资格事实（性别/色觉/语种/体检/政审意愿/专项资格），
                                      // 用于资格过滤谓词求值，不进入求解器
    preferenceProfile: {             // 问卷/专家启发得到的原型偏好，可为不确定变量的期望值形式
      pi: number[],                  // 原型权重（已折叠为确定性期望，若上游是不确定变量已在此之前完成 B2/B4 折叠）
      riskAversion?: {...}           // 可选，B6 边界内的凹效用参数（期望效用型风险厌恶，v2）
    },
    riskTolerancePolicyConfig: {     // 产品/政策配置常数，非学生输入，随查询附带（版本化）
      quotaBuckets: {reach, steady, safety},  // 配额分段边界，带出处
      safetyThreshold: number,       // 配额 DP 的阈值常数（若启用配额约束）
    }
  },
  candidatePool: RawProgram[],        // 资格过滤前的候选宇宙（T1 当年数据 + T3 计划 + T5 跨年映射，
                                      // 已按学生 province/subjectType/batch 限定，对应现有
                                      // candidateProjection.ts 的 loadPrograms 查询范围）
  capacity: number                    // 志愿容量 n（产品配置，随年份/批次变化）
}
```

### 5.2 输出：求解器输入数据结构

```
SolverInput {
  candidates: Array<{
    id: string,                       // T1 主键投影
    p: number,                        // ∈[0,1]，M 区计算的最终 p_i（含删失似然拟合链条，见 §3.1）
    v: number,                        // ≥0，M 区计算的 v̂_i（原型加权折叠，见 §3.2）
    // 以下字段不进入 DP 递推，只用于配额约束/审计追溯，随候选元组一起携带：
    _meta: {
      pSource: string,                // p_i 来源标注（"calibrated" / "backfilled_low_confidence" / "censored_le" 等，
                                       // 呼应 02_censoring_treatment.md 的来源追溯纪律）
      pConfidenceBand?: [number, number],  // 若该候选落在删失/聚合区间，携带置信带而非假装是点估计
      vComponents?: number[],         // 原型价值向量（审计用，可选，用于双计入检查）
    }
  }>,
  capacity: number,                   // = n
  quota?: { threshold: number, minCount: number }  // 若启用配额 DP，否则省略走无约束 DP
}
```

**契约边界声明**：
1. `SolverInput.candidates` 已经是**资格过滤后**的列表（ALG7 内核纯净性门要求）；
   过滤发生在 M 区内部，`SolverQuery.student.eligibilityFacts` 消费在先，不出现在 `SolverInput` 里。
2. `SolverInput.candidates` 中每个元组只有 `(id, p, v)` 三个字段是求解器**必需**消费的；
   `_meta` 字段是审计/产品展示层需要，求解器实现应可以忽略它们而不影响正确性
   （即求解器函数签名的最小契约是 `(id, p, v)[]` + `capacity` + 可选 `quota`）。
3. `v` 必须是**已排序前**的原始值——排序（v 降序）是求解器内部第一步，不要求 M 区预先排序，
   但 M 区**不得**打乱 `p_i`/`v_i` 的对应关系（每个 id 唯一对应一对数值，这是最容易出错的
   工程细节，尤其在多个中间派生步骤之后）。
4. 任何一个候选若其 `p` 或 `v` 派生过程中遇到"完全缺失需外部"字段（§4 表）却没有外部数据可用，
   **该候选不应进入 `SolverInput.candidates`**，而应落入 M 区自己的异常台账（呼应 D 区 P2"无声即错"
   纪律的 M 区版本：无法产出合法 (p,v) 元组的候选，宁缺勿错，不用占位值填充喂给求解器）。

## 6. 待后续 M 区分工确认的开放点（不阻塞本备忘交付，登记供主循环调度）

1. 配额 DP 目前只验证了单一"≥q 个 p≥0.8"约束；若产品侧最终要三段式冲稳保配额同时约束，
   需要算法侧agent确认状态维扩展的复杂度是否仍在 ALG4 性能门（2000 候选×96 志愿位 ≤100ms）内。
2. `_meta.pConfidenceBand` 这类置信带信息目前求解器不消费——若后续要做"网络化 CVaR/分位数报告"
   （雷区 §7-5 第 5 条的产品折中"期望优化+分位数报告"），需要另一条独立于 DP 主链路的报告管线
   消费这些置信带，本备忘不展开设计（属于报告层而非求解器输入契约）。
3. `v_dead`/`r_c`（A5/A6 v2 退档折扣）在山东主线退化，但若模型要推广到专业组省份（`research_directions`
   §7.7 提及的一般化方向），届时 `SolverInput.candidates` 元组需要从 `(id,p,v)` 扩展为 `(id,p,ṽ)`
   ——扩展点已在 LEMMAS A5 证明"结构与 BSAA 同构，交换论证/DP 对 (p,ṽ) 原样成立"，
   即接口契约本身不需要改变字段*类型*，只需要 M 区把 v 换成算好的 ṽ 再交付，求解器无感。
